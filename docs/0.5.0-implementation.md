# 0.5.0 implementation and validation

This candidate is developed in [draft PR #41](https://github.com/atlasru/dot/pull/41). No 0.5.0 tag or GitHub Release is created by this work. Existing 0.3.0/0.4.0 assets remain untouched. Full diagnostic semantics and platform limitations are in [DIAGNOSTICS.md](DIAGNOSTICS.md); candidate release notes are in [releases/0.5.0.md](releases/0.5.0.md).

## Implementation

- Android typed PingMethod/PingSettings/PingResult, SettingsRepository, private-process PingService/PingEngine and NodeDiagnostics lifecycle controller. Native test conversion moved out of UI. Deterministic node identities preserve the new cache and AUTO exclusions across reloads.
- Windows typed settings/diagnostics, bounded shared worker pool, process/config cleanup, active-VPN routing restrictions and transactional state persistence. Legacy diagnostic numbers remain stored but are not consumed as new measurements.
- Both platforms: GET/HEAD/TCP/actual ICMP, conservative all-attempt success policy, monotonic timing, metadata, compatible sorting, verified-only AUTO with exclusions/threshold, cancel/reset, startup/repeat diagnostics, numeric DNS/LAN bypass, subscription request controls, list display preferences and redacted metric/settings export.
- Android transient reconnect/backoff/network recovery controls; Windows existing tray behavior. Existing app split tunnel, themes, launcher icons, maps and subscription identity remain available.
- HY2 Android fix 852e5a7 is preserved; protocol-aware transport display adds protection for legacy HY2 fields on both platforms. VLESS transport parsing remains unchanged.
- Android versionCode 500 / versionName 0.5.0; Tauri/package/Cargo metadata 0.5.0. Core stays pinned to v26.7.28. Vite receives the minimal [8.1.6 security patch](https://github.com/vitejs/vite/releases/tag/v8.1.6); source-map-js moves to 1.2.2. Local npm audit reports zero findings after these changes.

## Validation matrix

The final chat report and PR checks identify the final successful Actions run and candidate artifacts. The workflow requires all of the following before assembling unified artifacts:

| Area | Validation |
| --- | --- |
| Android | `gradle testDebugUnitTest`, `gradle assembleDebug`, APK version/application ID/signature/license verification |
| Windows | Rust tests with `DOT_XRAY_EXE` pointing to pinned Xray, frontend typecheck/build/test, Tauri release executable, portable ZIP/provenance/license verification |
| Source | `scripts/verify-release.py`, synchronized metadata, no unfinished product markers |
| Diagnostics | HTTP GET/HEAD and 405/503 responses against local test servers/proxies; HTTP timeout/cancellation; aggregation; partial failure; method/URL cache isolation; bounded worker pool; direct TCP/HY2 guard; Windows actual ICMP loopback probe |
| Compatibility | VLESS TCP/TLS/REALITY and HY2 generated config acceptance by real Xray; HY2 UDP display and saved URI/legacy state regressions; settings validation/roundtrip/atomic failure/concurrent field edits; AUTO exclusions survive node renames; subscription identity and selection migration; sorting/AUTO eligibility |

Local frontend production build, typecheck, identity test and unified source checks passed. Local Rust compilation could not find MSVC link.exe, so native Windows verification uses the GitHub Windows runner. Local Android tool download encountered repeated connection resets; the GitHub Linux runner provides the complete Android SDK/Gradle/AAR build environment. These are environment limitations, not disabled checks.

**Not performed:** physical Android device tests, provider-authenticated VLESS/REALITY or HY2 VPN sessions, Windows live TUN route changes, connect/disconnect/reconnect/network handoff on real networks, and actual in-place app installation over 0.4.0. Unit/config/loopback checks are not evidence of those operations. Perform the device matrix before authorizing publication.

Settings that require additional platform/runtime work are deliberately absent: OS boot startup, Windows network-aware reconnect or app split tunnel, arbitrary core overrides, DoH/DoT presets, custom domain/IP rule editors, IP-family preference controls, kill switch and connection-timeout overrides. Advanced JSON export covers new settings; original theme/tray/icon/group-sort preferences stay in their existing stores. This is an explicit scope limitation, not a nonfunctional UI control.
